# SMS XML Ingestion Pipeline

Status: Completed

## Goal

Import SMS Backup & Restore XML files into Narada using an offline-first, streaming ingestion pipeline.

## Architecture

Phone
→ SMS Backup & Restore
→ Syncthing
→ Mandara
→ Narada Import Service
→ sms_messages

## Principles

- Raw SMS data is immutable
- Source XML remains the source of truth
- No financial classification in this issue
- No AI extraction in this issue
- No event generation in this issue
- Focus only on ingestion, normalization and persistence
- Support large XML files through streaming parsing

## Persistence Model

Narada stores SMS data in three layers:

sms_messages
→ sms_extractions
→ events

This issue implements only the first layer.

Future issues:

- #37 Financial SMS Classifier

## Database

### sms_messages

Fields:

- id
- address
- contact_name
- body
- sms_type
- received_at
- source_file
- import_batch
- raw_attributes (JSON)
- processing_status
- created_at

### processing_status

- PENDING
- PROCESSED
- FAILED

### raw_attributes

Stores original XML attributes not mapped to normalized columns.

Examples:

- protocol
- toa
- sc_toa
- service_center
- read
- status
- locked
- date_sent
- sub_id

### import_batch

Maps to SMS Backup & Restore backup_set value.

Used for:

- import auditing
- reprocessing
- troubleshooting

## Scope

## Acceptance Criteria

- Import 100k+ SMS records
- Stable memory usage
- Duplicate messages are skipped
- Import summary generated
- SMS records persisted successfully
