# Import / knowledge read APIs

Status: Completed

## Goal

Expose read-only HTTP APIs for imported SMS, import runs, and posted financial knowledge, matching `GET /events` pagination. Persist `sms_imports` so import history is queryable.

## Endpoints

```text
GET /imports
GET /imports/:id

GET /sms
GET /sms/:id

GET /knowledge
GET /knowledge/:id
```

## Behaviour

- Pagination: `page` (default 1), `limit` (default 10, max 100)
- Envelope: `{ items, pagination, filters }`
- No auth (same as `/events`)
- `GET /knowledge` wraps posted `financial_events` as `{ type: "financial", id: smsId, occurredAt, payload }`
- Knowledge `id` is `sms_messages.id`, not `financial_events.id` (rebuilds churn autoincrement)
- Unchanged XML (same path + mtime + size) is not re-parsed; a completed `sms_imports` row skips the run. Same mtime with a larger file (or a legacy row with no stored size) is re-parsed.

## Out of scope

- `GET /knowledge/search`
- `GET /timeline`
- Dashboards
- API keys

Query params and examples: [HTTP API](../../api.md).
